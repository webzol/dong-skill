# 公众号写稿风格参考（writing-style）

> 2026-11-16 起：用户指定下列范文为**主写作风格**；排版仍走 `gzh-skill`（默认 minimal-tech × dongpro）。  
> 本文件供写稿 Agent / 代码流水线读取；语料正文在同目录 `*-body.txt`，样式摘要在 `*-style.json`。

## 0. 怎么用

1. 选题确定后按 **§2 题材选腔**。按题材从写作风格库选 1–2 种口吻，总数含默认项。用户指定的风格优先，否则以最贴题的一种为默认。若有备选，用同一事实和图片另写一版正文，保持信源口径、图序和版式一致。生成或改写茶稿固定选两种不同口吻，按 [茶稿口吻](../../commands/chamo.md#茶稿口吻) 选定。纯排已定稿时保留原稿一个风格。
2. 写稿时强制套用 **§1 共用配方** + 该腔细则；不要混成「通稿腔」。
3. 排版阶段只消费成品 Markdown/HTML 骨架，**不要**再发明灰字导语、文内 h1、问句小标题套路收尾。
4. 助手可保留选题判断与事实核验；**口吻与节奏以本文件为准**。

## 1. 共用配方（所有题材）

- **标题**：爆点前置（结果 / 冲突 / 反差 / 「突发」「首次」「重磅」），信息密度高，少空形容词。
- **开篇**：禁止单独灰字导语；禁止文内重复大标题。第一段直接砸场——发生了啥 / 有多离谱 / 谁翻了谁。
- **段落**：短段推进；关键判断可单独成段加粗（卡兹克系尤甚）。
- **重点标注**（2026-11-16 新增，已纠正）：正文里的重点文字必须标出来，标注方式跟当前文章风格走（如短句加粗、单独成段加粗），**不要用橙色强调**。只标关键词或短句，不要整段刷强调。模型名/关键词可参考木易标注：浅底 `#EEF0F7` + 深蓝字 `#1F2F8F`（约 13px）；判断句用短句加粗。Markdown 阶段写成 `**重点**` 或关键词标记，排版时按该稿风格处理，**不上橙色**。
- **小标题**：结论式短钩子（「对数坐标都压不住」「轻量反杀旗舰」），**不要问句小标题**，不要说明书式点题，不带「一、二、三」。
- **证据**：官方图 / 原帖图 / 榜单原图优先；数字服务叙事，不堆阅读量、互动量。
- **口径**：官方 / 媒体 / 社区 / 博主观察分开写；未官宣标清。
- **收尾**：事实或一句判断后停；禁止「所以问题来了」式反问和万能金句；账号 CTA（点赞在看）可按号惯例，非必须。
- **去 AI 味**：少设问、少排比、少机器旁白；像真人编辑在赶热点。

### 1.1 科技稿隐藏水印

- 为公众号「斜杠资源君」新写科技 / AI / 大模型稿时，在每个写作版本的两处原创分析中各写一句有辨识度的短句。两句分置在不同段落，随上下文自然表达该稿的判断、对比或适用条件。用正常的汉字和标点，避开惯用语、其他文章用过的标记和来源原话。纯排定稿沿用原文。
- 这两句是可逐字检索的文字指纹。正常排版，正文里不显示公众号名、稿号或额外提示，也不使用零宽字符、隐形样式或标签属性。引用、译文、代码和第三方素材保留原样。
- 在同篇稿件的本地源稿目录 `generated/<date>/<slug>/watermark.md` 记录公众号「斜杠资源君」、稿件标题、每个写作版本及对应的两句原文。改动指纹时追加修订版本和日期，保留旧记录。发布后，拿到原文链接再补记。指纹对照只存本地，不进公开信源台账、Git 或交付 HTML 的注释。
- 打包前逐版核对两句都完整出现在对应的正文可见文本中。比对疑似搬运时，逐句查找并结合归档源稿、发布时间和原文链接核对。文字指纹适合追查保留原句的转载或摘抄。

## 3. 各腔细则

### 3.1 新智元腔

- 头可写「新智元报道」（若发斜杠资源君等自有号，**不要照抄账号头**，只学节奏）。
- 开篇短句砸场 → 身份/背景一句 → 核心物件（一张图、一个分数、一次夹取）→ 分节深挖。
- 小标题短、像海报文案；关键词与关键数字用加粗标注，**不要用橙色**（Markdown 阶段用 `**重点**` 即可）。
- 章节可用灰底白字条（排版层）；正文约 15–17px 量级。
- 图要多、要狠；视频按需。数字密集但每段只服务一个点。

#### 新智元·科研突破

- 风格选择器可直接使用「新智元·科研突破」。适合手里有研究声明、验证记录或独立复核材料，且读者需要理解验证过程的题材。
- 开篇先写谁公布了什么结果，紧接一句可追溯的声明或一个体现工作量的数字。回到此前的质疑，点出这次新增的证据。
- 中段按验证步骤推进。每段先用日常语言讲一个可能出错的地方，再交代谁用什么办法检查、结果如何。数字放在它所解释的那一步。
- 从记录里挑一个出人意料的细节作转折，再用读者能亲手算、亲眼看或凭经验判断的小例子解释抽象结论。
- 收尾交代结论的适用范围和下一项待验证的问题。措辞跟随一手材料的证据强度，区分作者自述、独立复核和同行评议。

### 3.2 卡兹克腔

- 第一人称/创作者视角；**一句一段**；「审美。」这类超短句单独成段加粗。
- 先甩离谱 case，再升到判断；少榜单堆砌。
- 几乎无橙装饰；黑字 + 粗 + 媒体穿插。
- 口语、设计师语感，允许一点自嘲，但不要灌水。

### 3.3 量子位腔

- 标题信息密度极高（谁对谁做了什么 + 关键数字）。
- 开篇带刺短句（「英伟达最近头疼的事儿可不止老黄那一件。」/「周五晚上搞事…」）。
- 权益类：爽点 → 清单 → 对比旧账；产业类：窗口期 + 内部口径 + 对手反应。
- 可穿插一句网感吐槽，但主体仍是硬事实。

### 3.4 ASI / 爆料腔

- 「重磅！」标题；作战室、联名、期权等关键词加粗标注，不要用橙色。
- 时间线/多方动作并置；未官宣必须标。
- 章节条分明，偏情报稿。


### 3.5 木易 / AI信息Gap 腔

- 范文：https://mp.weixin.qq.com/s/iq2S2WrVvN1amrOKbtSPtA 《AI 圈顶流 7000 字长文刷屏！超级智能最快明年就来》
- 开篇先砸结论（可引用核心判断），随后一句一段写结果和数字，不铺发现过程、不连续点名。
- 少用或不用小标题；靠短段和时间线把主要结果写完。
- 不写「X 用户」，少写「博主」；社区只需必要时用「网友」带过。
- 文字标注：关键词（尤其模型名）用浅底 `#EEF0F7` + 深蓝 `#1F2F8F`，只标词；关键句加粗；不要橙色。
- 排版引擎仍是 minimal-tech × dongpro，正文两端对齐按既有约定。



### 3.6 Mio 官宣稿

- 范文：自有成稿《谷歌正式发布 Gemini 4 Neon：AA 编码智能体榜第一，xhigh 智能指数 61 分排第 3》（2026-11-19），语料 `mio-谷歌正式发布-Gemini-4-Neon-官宣稿-*`。
- 用于模型正式发布、官宣配第三方跑分。排版以本篇为当前默认落地：minimal-tech × dongpro + 木易关键词标注，不用橙色，不用灰底章节条。
- 开篇第一句写发布本身，接着定位、定价/规格，再分节写榜单和案例，不铺发现过程。
- 小标题用结论短句，不用问句；跑分按榜单分开写，官方数和评测原帖有出入就并列写清；token 单价和单任务成本分开。
- 关键词（模型名、榜单名）用浅底 `#EEF0F7` + 深蓝 `#1F2F8F`；判断短句加粗，可单独成段。
- 只用官方图或评测原图；图注 5 到 10 个字；收束落到一句事实判断后停。
- 新智元 Hydrogen / 筷子夹飞船稿仍可作冲击力或场面参考，但同类官宣稿的排版和标注以本篇为准。

## 4. 排版对接（gzh-skill）

- 引擎：默认 **wx / minimal-tech × dongpro**（用户现行约定）。当前官宣稿落地见 `mio-谷歌正式发布-Gemini-4-Neon-官宣稿-style.json`：正文 15px / 行高 1.95 / `#141414` / justify；h2 17px/700；关键词芯片 `#EEF0F7` + `#1F2F8F` 13px；图注 12px `#8a8a8a` 居中。
- 正文 `text-align:justify`；文内 **禁止 h1**；禁止灰字导语块；禁止 lite 预览。
- **重点词标注（2026-11-22 定版落地）**：模型名 / 元素名 / 竞品名等关键词一律上芯片——`background:#EEF0F7;color:#1F2F8F;font-size:13px;padding:2px 5px;margin:0 2px`；判断句 / 金句用短句加粗；不用橙色。
- **双语卡片渐变底衬（2026-11-22 用户定版）**：白底大圆角卡浮于横向渐变底上——`linear-gradient(to right,#8f94fb,#4e54c8)`，四边 ≈18px@1x 渐变框，渐变烘进图片；卡上头像 / 昵称 / 认证徽章 / @handle 原样不动。生成脚本 `gzh-skill/engine-wx/scripts/tweet_cards.py`。
- **长图滑动框（2026-11-22 用户定版）**：竖排多行文字类长图（还原截图 / 长推文全文 / 榜单列表）一律套 §13c 滑动框——`height:320px` + `overflow-y:scroll` + 同款渐变底衬 wrapper（18px）+ 白字引导行，**禁渐隐 mask**，不看 2.5 屏阈值；规格唯一出处 `engine-wx/references/components.md` §13c。
- 配图：官方/原帖高清；禁止自绘信息卡；长图处理见上面「长图滑动框」条。
- 成稿：`E:\WX\<YYYY-MM-DD>\` + `generated/<日期>/`；机器不在则云端 `/workspace/wx-cloud/<日期>/`。
- 详细排版步骤仍读：`engine-wx/SKILL.md`、`DAILY_NEWS_WORKFLOW.md` §5–§7、`references/components.md`。

## 6. 给代码流水线的最小接口

写稿 prompt 组装建议：

```
SYSTEM/写作约束 = 本文件 §1 + §3 所选腔
USER = 选题事实包（官方链接、数字、配图路径、未官宣标记）
输出 = 中文正文 Markdown：无 YAML 导语；标题单独一行；小标题用 ## 结论短句；加粗表强调；图片用 {{IMG_n}} 占位
```

不要把范文全文塞进每次 prompt；只注入 §1+对应 §3 + 1～2 段开篇样例（从 `*-body.txt` 头 8～12 段截取）。
