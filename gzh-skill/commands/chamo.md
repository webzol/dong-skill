# 茶模型

凡涉及茶的内容，一律走这条线：主题固定 `tea-atelier`，模板按下表选择。

## 选模板

| 内容 | 首选 | 备选 |
|---|---|---|
| 茶知识 · 风味 / 参数 / 冲泡 / 存茶 | `tea-notes` | `tea-almanac` |
| 茶知识 · 时间 / 节气 / 一天四泡 | `tea-almanac` | `tea-notes` |
| 茶文化 · 茶史 / 点茶 / 茶礼 / 茶书茶画 | `tea-culture` | `tea-scroll` |
| 茶文化 · 公案 / 茶人 / 茶席随笔 | `tea-scroll` | `tea-culture` |
| 茶器 · 多器对比 / 怎么选 | `tea-ware` | `tea-catalog` |
| 茶器 · 单件拆解 / 部位 / 手感 | `tea-catalog` | `tea-ware` |
| 节日茶俗 · 春节/清明/端午/中秋/冬至等 | `tea-festival` | `tea-scroll` |
| 行业信息 · 新茶上市/价格行情/政策标准/展会财报 | `tea-industry` | `tea-notes` |

- 用户没说方向：先问一句「茶知识、茶文化，还是茶器？」，别自己猜。
- 用户只给了「茶」+ 一篇稿：按稿子内容判断；判断不出按 `tea-notes` 走。
- 已明确“茶知识”但没有选题或草稿：只问具体要解决的问题，不再追问三大方向。维护模板或技能的请求直接做维护，不自动写一篇文章。
- 茶知识写作或审稿先读 `gzh-skill/engine-wx/references/tea-knowledge.md`，按其中的选题、事实核验、参数与台账口径执行。
- **写正文前读 `gzh-skill/engine-wx/references/writing-style.md`**：茶稿同样守 §1 共用配方（开篇不写日期、不放灰字导语块、小标题结论式短句不用问句、收尾一句判断后停）；茶稿按下方茶类口吻选风格，通用风格库仅参考段落与论证写法。只做排版、草稿已定稿时可跳过。

## 茶稿口吻

- **茶席随笔**：从待客、布席、用器的具体动作写起，短段、留白，语气从容。茶文化、茶空间及茶器合写时默认用这一版。
- **茶事笔记**：围绕读者能观察或试做的细节写清步骤、判断与条件，语言平实。茶知识或偏实用的器物文章默认用这一版。
- 默认版与备选版用上面两个茶稿风格名，用户另行点名口吻时按当次要求处理。茶稿标题、正文、风格选择器均以茶题材的语言呈现。

## 硬规则

1. 正文**不放 h1**（公众号标题栏已有）、**不放灰字导语**、文末**不加页脚、不加来源列表**；
2. 图**内嵌在对应正文位置**，`display:block;width:100%;max-width:100%;height:auto;margin:14px 0 20px;`，**无边框、无圆角**。可按 [组件库 §13a](../engine-wx/references/components.md#13a-茶稿图注可选) 在图下加一句简短图注，建议 10–24 字；
3. 图片保留原始宽高比，长文字图按组件库 §13c 套滑动框；图片一律 base64，交付单文件 HTML（带右上角「复制到公众号」按钮）；
4. 不用底色卡片、圆角、阴影；表头底色只允许 `#f7f3ea`。表格用满栏固定布局，单元格顶对齐、正文允许换行，普通单元格内边距为 `9px 7px`。建议两列或三列，四列及以上或说明较长时拆成两列参数表或正文条目；
5. 宋体标题 + 苹方正文，15px / 1.95 行高 / 两端对齐；
6. 不写保健功效，不做「越陈越香」的绝对判断；冲泡建议给有依据的起始区间及适用条件，实测值和引用数据保持原值。

## 执行

1. 读模板骨架：`gzh-skill/engine-wx/templates/<模板>.md`；主题：`themes/tea-atelier.json`；口吻：`gzh-skill/engine-wx/references/writing-style.md`；
2. 生成或改写茶稿固定交付两种写作风格：按题材和用户指定选默认风格，写入 `generated/<date>/<slug>/body.html`，再从风格库选一种不同口吻，另写 `body-alt.html`。两版共用信源口径、事实、图片、图序、图注及同一茶模板和 `tea-atelier`，图片共用 `{{IMG_A}}` 等占位符。仅为定稿排版时保留原稿一版；
3. 配图放 `generated/<date>/<slug>/img/`，写 `images.json`；
4. 各版文本按校验器要求包 `<span leaf="">`，逐版先校验、再用 `inject_images.py --allow-missing-captions` 注入图片、再校验注入后的正文。全部通过后按 [统一打包流程](../SKILL.md) 用 `wrap_preview.py` 一次打包。双风格使用 `--default-label "默认风格名" --variant "备选风格名" <已注图的备选正文>`，打开显示默认版，点击切换查看并复制当前版；
5. 落盘 `E:\WX\<YYYY-MM-DD>\`，备份 `generated\<date>\<slug>\`；
6. 台账 `docs/sources/<date>-<slug>.md`（事实出处、适用条件、配图来源与修订记录），在 `docs/sources/<date>.md` 链接；保留 `body.html`、`images.json` 和源图用于后续改稿，交付目录只放成品；
7. `git add` → `commit` → `push`，回复报 commit 短号；
8. 交付三句用法。打开成品并按需切换写作风格 → 点「复制到公众号」→ 到公众号编辑器粘贴。结尾写「默认风格 = 实际口吻名」。

仅维护规则、未修改文章源稿时，不重生成历史文章；在台账与 `DEV_NOTES.md` 说明变更范围、验证结果及旧稿待核验项。提交推送遵守仓库授权边界；主分支推送未获确认时使用 `codex/` 分支。
